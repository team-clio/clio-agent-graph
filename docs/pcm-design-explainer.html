잊지 않는 팀

PCM은 문서, 코드, 해결한 문제에서 중요한 내용을 정리해 두고, 필요할 때 AI Agent가 근거와 함께 찾아보게 하는 프로젝트 장기기억입니다.

The problem

AI가 똑똑해도,
우리 프로젝트를 자동으로 알지는 못합니다

새 팀원이나 AI에게 같은 배경을 반복해서 설명하면 시간이 쌓입니다. 문서와 코드가 늘수록 “어디에 있는 정보가 최신인가?”도 불분명해집니다.

바뀌는 내용

프로젝트는 계속 변합니다. 예전 설명이 아직 맞는지 알기 어렵습니다.

PCM의 답: 프로젝트에서 확인된 내용을 주제별 “지식 노트”로 만들고, 언제 어떤 원문을 바탕으로 했는지 함께 보관합니다. Agent는 이 노트를 먼저 읽고, 필요하면 원문 코드나 문서까지 되짚습니다.

결과적으로 달라지는 점

“이 기능의 권한 규칙이 뭐였지?”라는 질문에, Agent가 프로젝트 맥락에 맞춰 답하고 근거도 제시할 수 있습니다.

중요한 구분

지식 노트는 원문을 대체하지 않습니다. 여러 원문을 이해하기 쉽게 요약·연결한 안내서이며, 원문은 언제나 다시 확인할 수 있습니다.

PCM architecture

PCM은 Agent와 저장소 사이에서
프로젝트 기억을 책임지는 서비스 계층입니다

전체 코드베이스에서 PCM의 핵심은 services/pcm/입니다. Graph는 언제 지식을 읽거나 갱신할지만 결정하고, PCM은 지식의 형식·출처·revision·snapshot 규칙을 일관되게 적용합니다.

왜 Protocol을 먼저 두나? Graph와 Agent는 “어떻게 저장하는지”를 몰라도 됩니다. 현재는 InMemoryPCM으로 규칙을 테스트하고, 이후 PostgreSQL·파일·Vector DB 구현으로 바꿔도 호출하는 쪽의 계약은 유지됩니다.

동일 실행은 같은 세계를 봅니다

분석 도중 새 지식이 commit되어도, 이미 시작한 실행은 고정된 snapshot의 지식과 Repository commit을 사용합니다.

과거를 덮어쓰지 않습니다

새 revision은 이전 revision의 유효 종료 시점을 기록합니다. 삭제도 물리 제거 대신 tombstone revision으로 표현합니다.

현재와 목표를 구분하면: InMemoryPCM에서 snapshot, revision 충돌, 멱등성, provenance, 프로젝트 격리 규칙은 구현·테스트되어 있습니다. PostgreSQL, immutable Markdown 저장, embedding과 hybrid index는 이 계약을 따를 다음 인프라 구현입니다.

Trust & safety

자동으로 정리하되,
근거와 변경 이력을 남깁니다

PCM은 AI가 만든 문장을 그대로 믿는 저장소가 아닙니다. 자동화가 하되, 무엇을 바꿨고 왜 바꿨는지 검증 가능한 형태로 남깁니다.

01 · 제안

AI가 새 지식 또는 수정안을 구조화된 형식으로 제안합니다.

02 · 검증

시스템이 출처, 형식, 이전 버전과의 연결을 확인합니다.

03 · 기록

통과한 변경만 새 버전으로 저장하고, 과거 버전도 보존합니다.

04 · 검색

키워드와 의미를 함께 사용해 필요한 내용을 찾습니다.

“언제 기준인가?”를 고정합니다

조사 시작 시점의 지식과 코드 버전을 함께 고정합니다. 조사 중 내용이 바뀌어도 답변의 기준이 흔들리지 않습니다.

Agent는 마음대로 쓰지 못합니다

Agent는 지식을 찾아 읽을 수만 있습니다. 실제 저장과 수정은 검증 절차를 가진 PCM 서비스가 담당합니다.

확인할 성공 기준의미
새 문서가 지식이 된다사람이 별도로 요약하지 않아도, 프로젝트 규칙이 검색 가능한 노트로 정리됩니다.
문서가 바뀌면 같은 주제가 갱신된다새 파일을 끝없이 쌓는 대신, 같은 주제의 최신 버전과 변경 이력을 관리합니다.
같은 요청은 한 번만 반영된다재시도나 중복 전달이 있어도 지식이 중복 생성되지 않습니다.
다른 프로젝트와 섞이지 않는다프로젝트마다 기억과 검색 결과가 분리됩니다.

Glossary

회의에서 이 네 가지만 알면 됩니다

지식 노트

프로젝트의 한 주제를 설명하는 Markdown 문서입니다. 예: “저장된 검색 권한 규칙”.

출처

지식 노트의 근거가 된 문서 단락, 코드 위치, 이슈를 가리키는 연결 정보입니다.

버전 (revision)

지식이 수정될 때마다 남는 번호입니다. 과거 내용과 변경 시점을 되돌아볼 수 있습니다.

스냅샷

조사에 사용하는 “그 시점의 프로젝트 모습”입니다. 지식과 코드를 같은 기준으로 묶습니다.

검색 색인

원하는 지식을 빠르게 찾기 위한 보조 데이터입니다. 손상돼도 지식 노트에서 다시 만들 수 있습니다.

Hybrid 검색

정확한 단어 찾기와 문맥상 비슷한 의미 찾기를 함께 하는 검색 방식입니다.

한 문장으로: PCM은 프로젝트의 중요한 맥락을 근거와 이력까지 갖춘 지식으로 바꾸어, 팀과 AI가 같은 이해를 공유하도록 돕는 서비스입니다.
